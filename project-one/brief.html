1. فكرة المشروع والهدف النهائي

هتعمل صفحة Portfolio لشخص بدأ شغله كـ Frontend Developer. الصفحة مش مجرد CV مكتوب؛ هي تجربة قصيرة تقنع الزائر إن صاحبها منظم، فاهم الأساسيات، وعنده شغل يقدر يعرضه.

الهدف التعليمي إنك تستخدم HTML علشان توصف معنى كل جزء، وبعدها تستخدم CSS علشان تعمل ترتيب بصري واضح من غير ما تعتمد على مكتبة جاهزة. JavaScript هنا دوره صغير جداً؛ لأن التركيز الأساسي على الهيكل والشكل.

اعتبر المشروع مكتمل لما حد يفتحه لأول مرة ويعرف بسرعة: إنت مين، بتعمل إيه، عندك إيه من مهارات، عملت إيه قبل كده، وإزاي يتواصل معاك.

2. إنت هتبني إيه؟

  • Header فيه اسمك وروابط داخلية لأقسام الصفحة.
  • Hero فيه جملة قوية عنك، وصف صغير، وزرارين واضحين.
  • About Section يشرح رحلتك وهدفك.
  • Skills Section فيها 3 بطاقات على الأقل.
  • Projects Section فيها 3 نماذج شغل مختلفة.
  • Contact Section فيها Form كاملة ورسالة نجاح تجريبية.
  • Footer فيه السنة الحالية ولينك يرجع لأول الصفحة.

اكتب محتوى حقيقي على قد ما تقدر. لو لسه معندكش مشاريع، اكتب مشاريع تدريبية نفسك تعملها ووضح إنها Concepts.

3. المهارات والمفاهيم اللي هتتدرّب عليها

HTML

هيكل الملف، Semantic Tags، ترتيب العناوين، Links، Lists، Forms، Labels، Input Types، وRequired Validation.

CSS

Selectors، Colors، Typography، Box Model، Spacing، Borders، Backgrounds، Flexbox، Hover/Focus، وMedia Queries.

JavaScript

اختيار عنصر واحد بـ querySelector، الاستماع لحدث submit، منع التحميل التجريبي بـ preventDefault، وتعديل نص رسالة.

مش مطلوب دلوقتي: Arrays، Objects، Loops، LocalStorage، أو رسم المحتوى من JavaScript.

4. هيكل HTML المطلوب

ابدأ بـ <!DOCTYPE html>، وحدد lang="ar" وdir="rtl". داخل head حط الترميز، الـ viewport، عنوان واضح، ووصل ملف CSS.

الـ Landmarks الأساسية

  • header للهوية والـ Navigation.
  • nav حوالين قائمة الروابط، ومعاه وصف مناسب لو عندك أكتر من Navigation.
  • main مرة واحدة حوالين المحتوى الأساسي.
  • section لكل جزء له عنوان واضح.
  • article لكل Skill أو Project Card تقدر تقراها لوحدها.
  • footer لمعلومات النهاية.

العناوين

استخدم h1 واحد لرسالتك الأساسية. كل Section تاخد h2، وعنوان كل Card يكون h3. متختارش مستوى العنوان علشان حجمه؛ الحجم مسؤولية CSS.

الـ Form

اعمل حقول للاسم، الإيميل، نوع المشروع، والرسالة. كل Input لازم يبقى له label مربوط عن طريق إن قيمة for تساوي الـ id. استخدم type="email" وrequired وminlength علشان المتصفح يساعدك في التحقق.

مهم: الـ Placeholder مش بديل للـ Label. أول ما المستخدم يكتب، الـ Placeholder بيختفي؛ إنما الـ Label بيفضل يوضح معنى الحقل.

5. تنسيق CSS المطلوب

ابدأ بالأساس

استخدم box-sizing: border-box لكل العناصر، شيل الـ margin الافتراضي من body، وحدد لون الخلفية والنص وline-height مريح. اعمل Class اسمه مثلاً .container يحدد أقصى عرض ويترك مساحة جانبية.

النظام البصري

اختار خلفية غامقة، لون Accent واحد واضح، لون نص أساسي، ولون نص ثانوي. كرر نفس قيم الـ Border Radius والمسافات علشان الصفحة تحس إنها نظام واحد مش أجزاء منفصلة.

Flexbox

استخدمه في الـ Navigation، صف الأزرار، بطاقات الـ Skills، ومعلومات الـ Footer. اسأل نفسك الأول: العناصر ماشية في صف ولا عمود؟ بعدها حدد display: flex وgap، وبعدين ظبط المحاذاة.

Responsive Design

ابدأ بشكل الموبايل. عند مساحة أكبر، خلي الـ Hero عمودين والبطاقات جنب بعض. متعتمدش على عرض ثابت؛ استخدم max-width، نسب، وflex-wrap.

حالات التفاعل

الأزرار والروابط لازم يبقى لها Hover، والأهم :focus-visible علشان مستخدم الـ Keyboard يعرف هو واقف فين. متشيلش الـ Outline من غير بديل أوضح.

6. منطق JavaScript المطلوب

المشروع ده محتاج Feature واحدة أساسية: لما المستخدم يبعت Form صحيحة، امنع الإرسال الحقيقي واعرض رسالة نجاح باسمه. محتاج كمان Feature صغيرة اختيارية لتحديث سنة الـ Footer.

  1. اختار الـ Form ورسالة الحالة.
  2. ضيف Event Listener لحدث submit.
  3. استخدم event.preventDefault() لأن مفيش Server يستقبل البيانات.
  4. خلي HTML Validation تشتغل قبل النجاح.
  5. اقرأ الاسم، وعدّل textContent لرسالة الحالة.
  6. اعمل Reset بعد النجاح فقط.

حط role="status" وaria-live="polite" على مكان الرسالة علشان Screen Reader يعلن التغيير.

7. كل Feature شغّالة إزاي وليه

التنقل داخل الصفحة

كل لينك في الـ Nav بيشير لـ ID موجود على Section: لينك href="#work" يروح لعنصر id="work". دي Navigation حقيقية من غير JavaScript.

البطاقات المرنة

الحاوية تستخدم Flexbox أو Grid، والبطاقات تاخد مساحة متساوية. لما الشاشة تصغر، العناصر تلف أو تتحول لعمود، فالمحتوى يفضل مقروء.

الـ HTML Validation

المتصفح يوقف الإرسال لو Required فاضي أو شكل الإيميل غلط. JavaScript تتعامل مع النجاح بس؛ كده كل تقنية بتعمل الدور المناسب ليها.

رسالة النجاح

حدث Submit يقرأ الاسم ويكتب رسالة شخصية. استخدام textContent أنسب من innerHTML لأننا بنعرض نص المستخدم ومش محتاجين HTML.

الـ Responsive Layout

الصفحة تبدأ بعمود واحد. Media Query واحدة أو اتنين يحولوا الأجزاء المناسبة لأعمدة لما العرض يسمح، من غير ما يصغر النص أو الأزرار زيادة.

8. ترتيب التنفيذ المقترح

  1. المحتوى الخام: اكتب كل الأقسام والعناوين والفقرات من غير CSS.
  2. Semantic Review: راجع إن كل عنصر مستخدم لمعناه وإن العناوين مرتبة.
  3. الأساس البصري: Body، Container، ألوان، خطوط، ومسافات.
  4. ترتيب الأقسام: Nav، Hero، Skills، Projects، Form باستخدام Flexbox.
  5. التفاصيل: Borders، Backgrounds، Buttons، Hover، وFocus.
  6. الموبايل: اختبر من 360px وخلي كل حاجة عمود واحد ومريحة.
  7. الشاشات الأكبر: ضيف Media Query للأعمدة والمسافات الأكبر.
  8. JavaScript: ضيف رسالة الـ Form بعد ما الصفحة نفسها تبقى كاملة.
  9. الاختبار: نفذ الـ Checklist كلها وسجل أي مشكلة تصلحها.

9. أمثلة صغيرة للمفاهيم الصعبة

ربط Label بـ Input

<label for="student-name">اسم الطالب</label>
<input id="student-name" name="studentName" type="text" required>

Flexbox بيلف العناصر

.cards {
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
}

.card {
  flex: 1 1 240px;
}

Media Query بسيطة

@media (min-width: 768px) {
  .intro {
    display: flex;
    align-items: center;
  }
}

الاستماع لإرسال Form صغيرة

const form = document.querySelector("#newsletter-form");

form.addEventListener("submit", function (event) {
  event.preventDefault();
  console.log("Form is valid and ready");
});

الأمثلة متعمدة تستخدم أسماء مختلفة ومش بتديك حل الـ Portfolio كامل. دورك تركب المفهوم في المكان الصح.

10. أخطاء شائعة وإزاي تتجنبها

  • كل حاجة div: ارجع لمعنى المحتوى واستخدم header/nav/main/section/article/footer.
  • أكتر من h1: خلي الرسالة الأساسية h1 وباقي عناوين الأقسام h2.
  • لينك من غير هدف: اتأكد إن كل href="#..." له ID مطابق بالظبط.
  • مسافات عشوائية: اختار مجموعة ثابتة زي 8، 12، 16، 24، 32px بدل أرقام مختلفة كل مرة.
  • عرض ثابت كبير: متكتبش width: 1200px لعنصر أساسي؛ استخدم width مرن وmax-width.
  • Placeholder بدل Label: اكتب الاتنين؛ كل واحد له وظيفة مختلفة.
  • Button من غير type: داخل Form حدد type="submit" أو type="button".
  • شيل الـ Outline: لو شلته لازم تضيف Focus Style أوضح، وإلا الصفحة تبقى صعبة بالـ Keyboard.
  • بدء JavaScript بدري: خلص المحتوى والـ CSS الأول؛ التفاعل هنا آخر خطوة.

11. Checklist الاختبار

  • الصفحة لها Title ووصف مناسب في Head.
  • فيه h1 واحد وكل Section لها h2 واضح.
  • كل روابط الـ Nav بتوصل للقسم الصح.
  • كل Project Card فيها عنوان ووصف وتقنيات.
  • كل Label مربوط بالحقل الصح.
  • الفورم ترفض اسم قصير، إيميل غلط، ورسالة قصيرة.
  • رسالة النجاح تظهر مرة واحدة باسم المستخدم.
  • الصفحة كاملة تتستخدم بالـ Keyboard والـ Focus واضح.
  • مفيش Scroll أفقي عند عرض 360px.
  • البطاقات تنتقل من عمود على الموبايل لأكتر من عمود على الشاشة الكبيرة.
  • الألوان مقروءة والنص الثانوي مش باهت زيادة.
  • Console مفيهاش Errors.

12. شروط اكتمال المشروع

المشروع يعتبر Core Complete لما يحقق كل النقط دي:

  • ملفات HTML وCSS وJavaScript منفصلة ومتصلة صح.
  • Header، Hero، About، Skills، Projects، Contact، وFooter موجودين.
  • HTML Semantic والعناوين مرتبة.
  • 3 Skills و3 Projects على الأقل.
  • Form Accessible فيها Validation ورسالة نجاح تجريبية.
  • Flexbox مستخدم بوضوح في جزئين على الأقل.
  • Responsive من 360px لحد شاشة Desktop.
  • Hover وFocus واضحين.
  • المحتوى مكتوب بصوتك ومش نسخة من الـ Simulation.

13. Bonus Challenges اختيارية

خلص الـ Core الأول، وبعدها اختار تحدي واحد فقط:

  1. ضيف Download Link لملف CV تجريبي باستخدام download، من غير ما تكسر الصفحة لو الملف مش موجود.
  2. اعمل Section آراء عملاء باستخدام blockquote وcite.
  3. ضيف CSS Animation خفيفة للـ Hero مع احترام prefers-reduced-motion.
  4. ضيف عدّاد حروف للرسالة بـ JavaScript، وحد أقصى واضح.
  5. اعمل Theme فاتح باستخدام Class واحدة على Body وزر بسيط، من غير LocalStorage في المستوى ده.
افتكر: Bonus كتير مش معناها مشروع أقوى. مشروع أساسي منظم، Accessible، ومختبر أهم من Features زيادة فيها مشاكل.
