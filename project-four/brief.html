1. فكرة المشروع والهدف النهائي

رحّال تطبيق لاكتشاف وجهات مصر وتنظيم رحلة بسيطة. المستخدم يبحث ويصفي ويرتب الوجهات، يفتح التفاصيل، يحفظ المفضلة، وبعدها يضيف محطات بتواريخ وعدد أيام ومسافرين. التطبيق يحسب ميزانية تقديرية ويحفظ المفضلة والرحلة.

الهدف التعليمي إنك تدير أكتر من جزء بيقرأ ويكتب في نفس الـ State من غير ما تعمل كود متكرر أو بيانات متعارضة.

حدود المشروع: مفيش API، Map، Booking، Payment، Accounts، أو Routing Library. كل البيانات Local علشان تركز على Frontend Architecture.

2. إنت هتبني إيه؟

  • Header فيها 3 View Tabs: اكتشف، المفضلة، رحلتي.
  • Dataset فيها 8 وجهات مصرية على الأقل.
  • Search + Region Filter + Category Filter + Sort + Count.
  • Reusable Destination Cards فيها Favorite وDetails وAdd to Trip.
  • Accessible Dialog للتفاصيل.
  • Favorites View مع Empty State وتزامن كامل.
  • Itinerary Form فيها وجهة، تاريخ، أيام، مسافرين، وملاحظة.
  • Add/Edit/Cancel/Delete لمحطات الرحلة.
  • Summary للمحطات والأيام والمسافرين والميزانية.
  • LocalStorage آمنة وحالات Error/Success/Empty/No Results/Recovery.

3. المهارات والمفاهيم اللي هتتدرّب عليها

Application State

Object مركزي فيه Active View، Search/Filters/Sort، Favorites IDs، Itinerary Array، وEditing ID.

Derived Data

نتائج البحث والمفضلة والإجماليات مش بيانات جديدة تتخزن؛ هي نتائج تتحسب من Dataset والـ State.

Reusable Rendering

Function واحدة تعمل Destination Card وتستخدمها Discover وFavorites. Functions منفصلة لرسم كل View.

Interactions

Event Delegation، Tabs، Dialog، Focus Return، Form Validation، CRUD، وStatus Announcements.

Persistence

Storage Schema فيه Favorites وItinerary فقط، Validation قبل الاستعمال، Versioned Key، وSafe Defaults.

4. هيكل HTML المطلوب

اعمل Header فيها Buttons للتنقل، وداخل Main اعمل 3 Sections، كل واحدة تحمل data-panel. JavaScript تظهر View واحدة وتخفي الباقي بـ hidden.

Discover

Form أو Toolbar للبحث والـ Selects، Result Count، Container للكروت، وNo-results State. الكروت نفسها تتولد من JavaScript.

Favorites

Container يعيد استخدام نفس الكروت، وEmpty State فيها زر يرجع لـ Discover.

Itinerary

Form كاملة، Error Region، Summary بـ dl، وol للمحطات لأن ترتيب الرحلة له معنى.

Dialog

استخدم dialog Native مع عنوان مربوط بـ aria-labelledby، Close Button، ومحتوى يتحدث. خلي الأزرار الحقيقية في HTML والنصوص Code-native.

5. تنسيق CSS المطلوب

اعمل App حقيقية مش Landing Page: Header هادية، Toolbar عملية، Results واضحة، وTrip Builder مركزة. استخدم ألوان Midnight مع Gold وTurquoise.

Destination Layout

خلي أول نتيجة Featured وباقي النتائج أكثر Compact. استخدم نفس Component لكن Variant Class، ومتعملش Card Grid متساوية بلا سبب.

CSS Travel Art

بدل صور خارجية، اعمل Art Panels من Gradients وPseudo-elements: سماء، شمس، جبال، أو بحر. كل Destination تاخد Class لون مختلف.

Responsive

Toolbar من 5 أعمدة إلى 2 ثم 1. Cards تتحول من Art + Copy إلى عمود. Itinerary Form وSummary يبقوا تحت بعض. Tabs تسمح بالـ Horizontal Scroll لو العرض ضيق.

States

Selected Tab، Favorite Pressed، Focus، Dialog Backdrop، Error، Success، Empty، No Results، وEdit Mode لازم كلهم واضحين.

7. كل Feature شغّالة إزاي وليه

View Switching

حدّث activeView، aria-pressed والـ Class على Buttons، وبعدها hidden على Panels. انقل Focus لعنوان الـ View الجديدة.

Search/Filter/Sort

ابدأ بنسخة من Dataset: Filter بالنص، ثم المنطقة، ثم الفئة، وبعدها Sort. متعملش Sort للـ Dataset الأصلية.

Reusable Cards

Function تستقبل Destination وIndex، تعمل Elements آمنة، وتقرأ Favorite State علشان تحدد شكل القلب. نفس Function تخدم صفحتين.

Favorites

لو ID موجود، شيله بـ Filter؛ لو مش موجود، Push. Save، وبعدها Render Discover وFavorites علشان الزرين يتزامنوا.

Details Dialog

املأ العناصر بـ textContent، خزّن الزر اللي فتحها، استخدم showModal، وحط Focus على Close. عند الإغلاق رجّع Focus للزر الأصلي. Escape والضغط على الخلفية يقفلوا.

Add to Trip

زر الوجهة ينقل لـ Itinerary، يحدد الوجهة في Form، ويحط Focus على التاريخ. الإضافة الفعلية تحصل بعد Validation.

Duplicate Policy

امنع نفس destinationId مع نفس startDate، إلا لو المستخدم بيعدل نفس Trip ID. اعرض Error واضح بدل إضافة نسخة.

Budget

لكل محطة: daily budget × days × travelers. إجمالي الرحلة Reduce لكل المحطات.

10. أخطاء شائعة وإزاي تتجنبها

  • نسخ Card Renderer مرتين: استخدم Function واحدة وVariant Class.
  • Sort يغير Dataset: اشتغل على Array مشتقة.
  • تخزين Destination Objects في Favorites: خزن IDs فقط.
  • عدم تزامن القلب: بعد Toggle ارسم Discover وFavorites.
  • Dialog من غير Focus: حدد Focus عند الفتح ورجعه عند الإغلاق.
  • HTML من User Note: استخدم textContent.
  • Duplicate Trips: افحص destination + date مع استثناء Editing ID.
  • Storage تقبل أي Shape: افحص IDs والأرقام والتواريخ قبل الدمج.
  • Function عملاقة: افصل Render وActions وStorage.
  • إضافة Features خارج الهدف: متضيفش Maps أو Booking قبل Core.
