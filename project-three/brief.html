03مصروفيافتح الـ Simulation

Project Brief · المستوى الثالث

ابني Expense Tracker ببيانات حقيقية

في المشروع ده الـ Array هي مصدر الحقيقة. الـ Form تغيّر البيانات، والواجهة تتعمل Render من البيانات، وLocalStorage تحفظها. لو فهمت الدورة دي، هتقدر تبني عشرات التطبيقات.

قبل ما تبدأ: جرّب Add/Edit/Delete والفلاتر في الـ Simulation، وبعدها اكتب الـ Data Shape على ورقة. متبدأش برسم Rows من JavaScript قبل ما تفهم كل Object بيمثل إيه.

1. فكرة المشروع والهدف النهائي

مصروفي تطبيق شخصي يسجل أي دخل أو مصروف. المستخدم يدخل الوصف والمبلغ والنوع والفئة والتاريخ، وبعد الحفظ تظهر العملية في القائمة وتتحدث 3 أرقام: الدخل، المصروفات، والرصيد.

الهدف الحقيقي مش العمليات الحسابية؛ الهدف تعمل Single Source of Truth. يعني متخزنش الرصيد في مكان والعمليات في مكان. خزّن العمليات فقط، وكل رقم ظاهر يتحسب منها.

البيانات تفضل موجودة بعد Reload باستخدام LocalStorage، ولو البيانات المحفوظة بايظة، التطبيق يتعافى بدل ما ينهار.

2. إنت هتبني إيه؟

  • 3 Summary Cards للرصيد والدخل والمصروفات.
  • Form فيها وصف، مبلغ، نوع، فئة، وتاريخ.
  • قائمة Operations بتترسم من Array.
  • Add وEdit وSave Edit وCancel Edit وDelete.
  • فلتر بالنوع وفلتر بالفئة وزر Reset.
  • LocalStorage بمفتاح مستقل.
  • Empty State لأول استخدام، No Results للفلاتر، Error للـ Form، وStatus للنجاح أو Recovery.

3. المهارات والمفاهيم اللي هتتدرّب عليها

Data

Arrays، Objects، Stable IDs، map، filter، find، reduce، وsort.

Functions

Functions صغيرة لكل مسؤولية: Load، Save، Validate، Render Summary، Render List، Start Edit، Reset Form.

DOM

createElement، textContent، append، replaceChildren، وEvent Delegation على القائمة.

Persistence

JSON.stringify وJSON.parse، Try/Catch، وفحص شكل البيانات قبل استخدامها.

4. هيكل HTML المطلوب

اعمل Sections منفصلة للـ Summary، Form، والTransactions. HTML توفر الـ Static Shell فقط؛ Rows نفسها هتتولد من JavaScript.

الـ Form

كل حقل له Label وName وType مناسب. المبلغ type="number" مع min="0.01" وstep="0.01". التاريخ type="date". زر الحفظ Submit وزر إلغاء التعديل Button عادي ومخفي في البداية.

الـ States

جهز عنصر Error بـ role="alert" وعنصر Status بـ role="status" aria-live="polite". اعمل Empty State وNo-results State كعناصر مستقلة JavaScript تظهر وتخفي بينهم.

القائمة

استخدم ul لأن دي مجموعة عمليات. كل عملية هتكون li، وأزرارها تحمل data-action وdata-id.

5. تنسيق CSS المطلوب

استخدم Dashboard مفتوحة: Summary في صف، Form في Band كبيرة، وبعدها List واضحة. متحطش كل قيمة في Card صغيرة لمجرد إنها Card.

الفرق بين النوعين

الدخل أخضر والمصروف Coral/أحمر، لكن متعتمدش على اللون بس: اكتب “دخل ↑” و“مصروف ↓”.

القائمة Responsive

على Desktop خليها شبه Table باستخدام Grid Columns. على Mobile اخفي Header وحوّل كل Row لتخطيط من عمودين مع الوصف والإجراءات بعرض كامل.

الحالات

صمم Error، Success، Empty، No Results، Edit Mode، Hover، Focus، وDisabled. الحالة جزء من المنتج، مش حاجة تتضاف في الآخر.

6. منطق JavaScript المطلوب

شكل الـ Transaction

{

  description: "راتب شهر مايو",
  amount: 1500,
  type: "income",
  category: "salary",
  date: "2026-07-26"

ابدأ بـ let transactions = [] وlet editingId = null. وقت Submit، اجمع القيم واعمل Validate. لو إضافة: Push Object جديد. لو تعديل: استخدم Map واستبدل Object اللي ID بتاعه يساوي editingId.

بعد أي Mutation نفّذ نفس السلسلة: Save → Reset Form عند الحاجة → Render. الفلاتر تعمل Render فقط ومينفعش تغير الـ Array الأصلية.

Storage Key لازم يكون codehub-expense-tracker-v1. النسخة في الاسم تديك فرصة تغير شكل البيانات مستقبلاً من غير ما تلخبط القديم.

7. كل Feature شغّالة إزاي وليه

Add

Validate القيم، اعمل ID ثابت، ضيف Object، Save، وبعدها Render كل شيء. متضيفش Row مباشرة وبس؛ الـ Row لازم تكون نتيجة للـ Array.

Edit

Find العملية بالـ ID، املأ الحقول، خزّن ID في editingId، وغير عنوان وزر الـ Form. عند الحفظ استبدل نفس الـ Object مع الحفاظ على ID.

Cancel

امسح editingId، Reset الحقول، رجع النصوص للوضع الأساسي، وانقل Focus لأول حقل.

Delete

Filter الـ Array وخلي كل العناصر اللي ID بتاعها مختلف. Save وRender وعلن رسالة نجاح.

Totals

Filter الدخل والمصروف، وبعدها Reduce لكل مجموعة. الرصيد = الدخل − المصروف. احسب من كل البيانات حتى لو القائمة مفلترة.

Filters

اشتغل على نسخة مشتقة: Type Filter ثم Category Filter ثم Sort. متغيرش transactions نفسها.

LocalStorage

Load مرة في البداية، Save بعد Mutation فقط. Wrap الـ Parse في Try/Catch وافحص إن الناتج Array وإن كل Item له الشكل المتوقع.

10. أخطاء شائعة وإزاي تتجنبها

  • تخزين totals: خزن العمليات واحسب totals منها.
  • المبلغ String: استخدم Number وتأكد إنه finite وأكبر من صفر.
  • index كـ ID: الترتيب يتغير؛ استخدم ID ثابت.
  • فلترة الـ State الأصلية: اعمل Derived Array وسيب الأصل كما هو.
  • innerHTML مع Input: استخدم createElement وtextContent.
  • Parse من غير Try/Catch: قيمة تالفة ممكن توقف التطبيق كله.
  • Edit يضيف نسخة: افصل وضع الإضافة عن التعديل بـ editingId.
  • نسيان Save بعد Delete/Edit: خلي كل Mutation واضحة وتتبعها Save.
  • تحديث جزء واحد: نادِ Render المركزية بعد التغيير.

11. Checklist الاختبار

  • أول فتح يظهر Empty State.
  • وصف قصير أو مبلغ صفر يظهر Error.
  • عملية دخل صحيحة تحدث القائمة والدخل والرصيد.
  • عملية مصروف تحدث المصروفات وتقلل الرصيد.
  • Edit يحفظ فوق نفس ID ولا يكرر العملية.
  • Cancel لا يغير البيانات.
  • Delete تحدث كل الإجماليات.
  • كل Filter وحده والاتنين مع بعض صحيحين.
  • No-results تظهر فقط لو عندك بيانات ومفيش Match.
  • Reset Filter يرجع القائمة كلها.
  • Reload يرجع البيانات.
  • JSON تالف يتشال والتطبيق يفضل شغال.
  • النص اللي فيه <tag> يظهر كنص مش HTML.
  • كل شيء قابل للاستخدام بالـ Keyboard.
  • 360px من غير Scroll أفقي.

12. شروط اكتمال المشروع

  • Array of Objects هي مصدر الحقيقة الوحيد.
  • Add/Edit/Cancel/Delete مكتملين.
  • Validation تمنع القيم غير الصحيحة.
  • Totals مشتقة ودقيقة.
  • Filters لا تغيّر البيانات الأصلية.
  • LocalStorage آمنة ومفتاحها مستقل.
  • Empty/Error/No-results/Success States موجودة.
  • رسم مدخلات المستخدم آمن.
  • الـ Layout Responsive وAccessible.
  • Console من غير Errors.
