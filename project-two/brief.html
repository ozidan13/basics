1. فكرة المشروع والهدف النهائي

CaseCraft أداة تخلي العميل يشوف جراب الموبايل قبل ما يطلبه. يختار الموديل واللون والنقشة، يكتب اسمه، يحدد الكمية، والواجهة تعرض الشكل والسعر والملخص فوراً.

التحدي هنا إن عندك كذا Control بيأثر على كذا مكان. لازم تعرف إيه العنصر اللي أطلق الـ Event، تقرأ قيمته، تحدّث الـ Preview، وتخلي كل المعلومات متوافقة.

الهدف النهائي: واجهة Responsive شغالة بالكامل من غير Framework، ومن غير تخزين بيانات أو رسم خيارات من Array.

2. إنت هتبني إيه؟

  • Workspace متقسم Preview، Controls، وOrder Summary.
  • 3 أزرار لموديلات بأسعار مختلفة.
  • 3 Color Swatches تغير لون الجراب.
  • 3 Pattern Controls تغير Class على الـ Preview.
  • Input للاسم بحد أقصى 12 حرف وعدّاد.
  • Quantity Stepper من 1 إلى 5.
  • حساب Total، Reset، ورسالة Add to Cart تجريبية.
مفيش Checkout حقيقي ومفيش بيانات بتتبعت. “السلة” هنا Feedback بصري فقط علشان تتدرب على UI State.

3. المهارات والمفاهيم اللي هتتدرّب عليها

Layout

CSS Grid للـ Workspace الرئيسي، Flexbox لمجموعات الاختيارات، وBreakpoints لتحويل 3 أعمدة لعمود واحد.

DOM

querySelector وquerySelectorAll، Event Listeners، event.currentTarget، dataset، classList، وtextContent.

حالة الواجهة

قيم بسيطة للموديل والسعر والنقشة والكمية. مش هتعمل Array منتجات ولا State Manager؛ ده ييجي في المستوى الجاي.

Accessibility

button حقيقية، fieldset وlegend للمجموعات، aria-pressed للاختيار، وaria-live للرسائل.

4. هيكل HTML المطلوب

خلي الـ Main Container فيه 3 أجزاء: Section للـ Preview، Form أو Section للـ Controls، وAside للملخص. استخدم Footer صغير للحالة المباشرة لو حابب.

الأزرار وقيم data-*

كل اختيار لازم يبقى button type="button". حط القيمة اللي JavaScript محتاجاها في Attribute واضح: data-price، data-color، أو data-pattern. النص الظاهر يشرح الاختيار للإنسان، والـ Data Attribute تدي الكود قيمة منظمة.

تجميع الاختيارات

استخدم fieldset حوالين كل مجموعة وlegend بعنوانها. ده يوضح العلاقة بين الأزرار لمستخدم Screen Reader.

الملخص

عنصر dl مناسب جداً لمفتاح وقيمة: “الموديل / iPhone 14 Pro”. كل صف يحتوي dt وdd. السعر النهائي ممكن يكون output أو عنصر نصي واضح.

5. تنسيق CSS المطلوب

Grid الرئيسي

على Desktop استخدم 3 أعمدة: Preview أوسع، Controls متوسطة، Summary أصغر. على Tablet خلي Summary صف كامل، وعلى Mobile خليهم تحت بعض.

الجراب من CSS

اعمل Rectangle طويل بـ Border Radius كبير، Border غامق، وCamera Bump. لون الجراب يبقى CSS Custom Property مثل --case-color علشان JavaScript تغيره بسطر واحد.

النقشات

اعمل Classes منفصلة مثل .pattern-dots و.pattern-lines. كل Class تستخدم Gradient مختلف على Pseudo-element فوق اللون الأساسي.

الحالات

اعمل Class واحدة اسمها .is-selected تتكرر على كل أنواع الاختيارات. لازم الاختيار الحالي يبقى واضح بالـ Border والـ Background، مش باللون لوحده.

Controls

خلي أقل ارتفاع للزر مناسب للمس، والـ Disabled Button واضح. متصغّرش النص علشان كل الأعمدة تدخل؛ سيب الـ Layout يتغير.

6. منطق JavaScript المطلوب

قسم الكود لخمس أجزاء واضحة:

  1. Selectors: امسك مجموعات الأزرار والـ Inputs والـ Outputs.
  2. Current values: متغير للسعر الأساسي، سعر النقشة، الكمية، وأسماء الاختيارات.
  3. Helper: Function تشيل .is-selected من المجموعة وتضيفها للزر الجديد، وتحدّث aria-pressed.
  4. Render/update: Function واحدة تحسب الإجمالي وتحدث كل النصوص والأزرار.
  5. Events: Event Listener لكل مجموعة، وInput Event للاسم، وClick للكمية والـ Reset.

الحساب: (basePrice + patternPrice) * quantity. حوّل قيم dataset من String إلى Number قبل الجمع.

7. كل Feature شغّالة إزاي وليه

اختيار الموديل

الضغط يحدد الزر، يقرأ الاسم والسعر من Dataset، وبعدها ينادي Update واحدة. كده الحساب والملخص يتغيروا من مكان مركزي.

اختيار اللون

JavaScript تحدث CSS Custom Property على عنصر الجراب. CSS يفضل مسؤول عن الرسم، وJavaScript مسؤول عن اختيار القيمة فقط.

اختيار النقشة

شيل كل Pattern Classes المعروفة، وضيف Class الاختيار الجديد. متسيبش Class قديمة وإلا النقشات تتداخل.

كتابة الاسم

استخدم Event اسمه input علشان التغيير يحصل مع كل حرف. لو القيمة فاضية، اعرض نص بديل مفهوم بدل مساحة فارغة.

الكمية

استخدم Math.max وMath.min أو Conditions تمنع النزول عن 1 والزيادة عن 5. عطّل الزر عند الحد المناسب.

Reset

رجّع كل قيمة للـ Default، رجّع الـ Classes وaria-pressed، امسح الرسالة القديمة، وبعدها Update واحدة.

9. أمثلة صغيرة للمفاهيم الصعبة

قراءة Dataset

<button data-size="large" data-extra="30">Large</button>

const button = document.querySelector("[data-size]");
const size = button.dataset.size;
const extra = Number(button.dataset.extra);

Selected State موحدة

buttons.forEach(function (button) {
  const selected = button === clickedButton;
  button.classList.toggle("is-selected", selected);
  button.setAttribute("aria-pressed", selected);
});

تغيير CSS Variable

preview.style.setProperty("--accent-color", "#ff5f82");

حماية رقم بين حدين

count = Math.min(10, count + 1);
count = Math.max(1, count - 1);

10. أخطاء شائعة وإزاي تتجنبها

  • نسيان type="button": الزر داخل Form ممكن يعمل Submit بالغلط.
  • جمع Strings: قيمة Dataset نص؛ استخدم Number قبل العمليات الحسابية.
  • Selected على كذا زر: شيل الحالة من المجموعة كلها قبل ما تضيف الجديدة.
  • تحديث مكان ونسيان التاني: خلي Function واحدة مسؤولة عن الملخص والحساب.
  • استخدام innerHTML للاسم: استخدم textContent لأن القيمة جاية من المستخدم.
  • لون من غير وصف: Swatch لازم لها اسم ظاهر أو aria-label.
  • Stepper خارج الحدود: اختبر 1 و5 وعطّل الزر المناسب.
  • كل حاجة Absolute: Absolute مناسب لرسم الجراب، مش للـ Layout الرئيسي.

11. Checklist الاختبار

  • كل موديل يغيّر الاسم والسعر.
  • اختيار واحد فقط فعال في كل مجموعة.
  • aria-pressed تساوي الحالة البصرية.
  • كل لون يظهر على الجراب ونقطة الملخص.
  • كل نقشة تشيل النقشة القديمة.
  • الاسم يتحدث مع كل حرف ولا يزيد عن 12.
  • الاسم الفاضي له بديل مفهوم.
  • الكمية لا تقل عن 1 ولا تزيد عن 5.
  • الإجمالي صحيح مع كل تركيبة.
  • Reset يرجع كل Default.
  • Add to Cart تعرض رسالة واحدة واضحة.
  • كل Control يشتغل بالـ Keyboard.
  • الواجهة بدون Scroll أفقي عند 360px.
  • Reload يرجع Defaults لأن مفيش تخزين.

12. شروط اكتمال المشروع
